# ClipFlow 2.0 重设计规格

状态：已批准的设计，等待书面规格复核

日期：2026-07-10

## 1. 目标

ClipFlow 2.0 要把现有菜单栏剪贴板工具升级为一个键盘优先、默认本地、数据可靠的 macOS 应用。第一任务是让用户用最少操作找回并复制历史内容；第二任务是提供完整历史管理、分类与可选 AI 处理。

本次工作同时覆盖：

- 重做菜单栏快速面板、完整历史窗口和设置窗口。
- 修复选择状态、AI 异步写回、保留期清理、数据库假成功、快捷键冲突等已确认问题。
- 建立明确的隐私边界、AI 网络边界、错误反馈和诊断策略。
- 新增可执行测试、性能门槛、版本体系和可重复发布流程。

## 2. 已确认的现状问题

当前代码审计确认了以下高优先级问题：

- AI 任务完成时重新读取当前选中项，可能把记录 A 的结果写入记录 B。
- ClipboardItem 是值类型，但列表与 selectedItem 各保存一份状态，收藏、分类、摘要和清理后会互相脱节。
- 分类栏的展开按钮位于分类栏内部，收起后没有恢复入口。
- 修改保留期会直接删除数据库记录，却不更新内存列表。
- 数据库错误仅打印日志，界面仍按成功路径修改内存，重启后出现回滚或数据丢失。
- 相同内容再次复制时被永久去重，不会更新到列表顶部。
- 保留期清理只在启动或设置变化时运行，常驻应用会长期保留过期内容。
- Ollama 地址允许任意 HTTP 主机，完整剪贴板可能明文发送到远端，与“完全本地”承诺冲突。
- Ollama 不可用时会通过环境 PATH 自动启动进程，且探测请求、任务状态和取消缺少可靠控制。
- 快捷键注册结果未检查，冲突后旧快捷键被注销且用户没有错误反馈。
- 主面板缺少原生列表选择、键盘导航、辅助功能标签和稳定的焦点路径。
- 项目没有 XCTest target；现有脚本主要检查源码文本形状，无法覆盖持久化、并发和 UI 行为。

## 3. 产品原则

1. 极速找回优先。打开面板、搜索、选择和复制必须形成完整键盘路径。
2. 单一事实来源。界面不得持有可与数据库状态分叉的记录副本。
3. 写入成功才更新界面。任何持久化失败都必须可见、可重试。
4. 默认本地。未明确授权时，不向非回环地址发送剪贴板内容。
5. 危险操作可恢复。单项删除支持撤销，批量删除显示范围并确认。
6. 原生 macOS 体验。优先使用系统列表、工具栏、设置窗口、焦点和辅助功能语义。
7. 规格可验证。每项关键行为都必须对应自动化测试或明确的人工验收步骤。

## 4. 范围与非目标

### 4.1 本次范围

- 文本剪贴板捕获、检索、复制、收藏、分类、删除和保留期管理。
- 菜单栏快速面板与可调整大小的完整历史窗口。
- 本地规则处理、本地 Ollama，以及显式授权的远程 HTTPS 模型。
- 应用排除、敏感内容保护、监听暂停和脱敏诊断。
- Swift 并发安全、SQLite 事务与迁移、XCTest 和发布脚本。

### 4.2 非目标

- 图片、文件和富文本剪贴板。2.0 明确只支持文本；现有未闭环的 image/file 声明不作为可用能力。
- iCloud、跨设备同步、团队共享或账户系统。
- 自研数据库端到端加密。数据库使用用户级权限并依赖系统磁盘加密；产品不得宣称自身提供端到端加密。
- Mac App Store 发布。目标是 Developer ID 分发；正式签名和公证仍依赖外部证书。
- 自动下载、安装或静默启动 Ollama。

## 5. 体验架构

### 5.1 菜单栏快速面板

快速面板默认尺寸为 440 × 520 点，只承载高频检索与复制，不再放入三栏详情、批量管理或完整 AI 工作流。

布局从上到下为：

- 顶部状态栏：ClipFlow、监听状态、暂停菜单、打开完整历史按钮。
- 搜索框：面板打开后自动获得焦点。
- 智能筛选：最近与收藏。
- 原生选择列表：显示内容预览、分类、时间和收藏状态。
- 底部状态：结果数量、当前快捷键和最近错误入口。

键盘行为：

- 上下方向键移动选择。
- Return 复制选中内容并关闭面板。
- Command-Return 在完整历史窗口中打开选中记录。
- Command-F 聚焦搜索。
- Command-Shift-F 切换收藏。
- Delete 请求删除并提供撤销。
- Escape 清空搜索；搜索为空时关闭面板。

常用操作不得依赖悬停。复制和收藏可通过列表行尾按钮、键盘和上下文菜单访问；删除放在上下文菜单与键盘命令中。

暂停菜单提供暂停 5 分钟、暂停 1 小时和暂停到手动恢复。暂停状态与剩余时间在快速面板顶部持续可见。

鼠标单击只选择记录，双击执行复制并关闭快速面板；README 和界面提示必须使用相同表述。

### 5.2 完整历史窗口

完整历史窗口默认尺寸为 1040 × 680 点，最小尺寸为 760 × 520 点，可调整大小并恢复上次位置。

窗口使用三栏布局：

- 侧栏：全部、收藏、今天等智能集合，以及按稳定顺序显示的内置和自定义分类。
- 内容栏：可搜索、可选择、可分页加载的历史列表。
- 详情栏：可滚动的内容、元数据、分类和 AI 工具。

侧栏开关位于始终可见的工具栏，避免收起后无法恢复。窄窗口下详情栏可折叠为导航目标，不能通过压缩产生不可读的小字号。

详情底部固定复制主操作；长内容和 AI 结果在同一滚动容器中。摘要与改写使用不同状态：摘要可持久化，改写默认仅在当前会话保留，用户可复制结果但不会覆盖原始剪贴板记录。

### 5.3 设置窗口

设置使用标准 macOS 设置窗口，默认尺寸为 560 × 460 点，不绘制重复标题栏或自定义关闭按钮。

设置分为：

- 通用：保留期、启动行为、最大单条文本、监听控制。
- 快捷键：当前快捷键、录制、冲突反馈和恢复默认。
- 隐私：排除应用、敏感内容保护、数据库位置和清除数据。
- 分类：自定义分类、排序、删除时迁移策略。
- AI：关闭、本地 Ollama、远程 HTTPS 三种模式及其隐私说明。
- 诊断：版本、连接状态、脱敏错误和诊断导出。

API 调用记录不再保存原文或生成结果，只保存操作类型、时间、模型、耗时和成功状态。

保留期默认 15 天，可选 1 至 365 天或永不自动清理。改变保留期时先显示将被删除的非收藏记录数量；用户确认后才执行清理。

### 5.4 窗口与应用行为

应用启动后保持菜单栏形态。打开完整历史时应用激活并把窗口带到前台；关闭所有普通窗口后仍在菜单栏运行。Command-, 始终打开设置，Command-Q 退出应用。

### 5.5 视觉与辅助功能

- 使用系统字号、控制尺寸、List、NavigationSplitView、Toolbar 和语义色。
- 正文不低于系统默认小号文本；不使用 9 点正文表达关键信息。
- 分类不能只依赖颜色区分；图标、文本和辅助功能标签共同传达含义。
- 所有图标按钮提供可访问名称、提示和至少 28 × 28 点命中区域。
- 覆盖浅色、深色、增强对比度、减少透明度和 VoiceOver。
- 自定义材质仅用于窗口层级与顶部 chrome，不在内容区堆叠多层半透明卡片。

## 6. 组件与职责

### 6.1 AppCoordinator

负责菜单栏项目、快速面板、完整历史窗口、设置窗口、主菜单和应用激活策略。它只协调窗口，不拥有剪贴板业务数据。

### 6.2 ClipboardStore

ClipboardStore 是 MainActor 隔离的唯一 UI 状态源，负责：

- 当前查询、筛选、分页结果和 selectedItemID。
- 从记录集合派生 selectedItem。
- 调用 Repository 和服务层并把结果转换为界面状态。
- 管理成功提示、可恢复错误和 Undo 操作。

SwiftUI 视图通过注入的 Store 工作，不再直接访问多个 shared 单例。

### 6.3 ClipboardRepository

ClipboardRepository 是 actor 隔离的 SQLite 访问层，所有方法均返回值或抛出类型化错误。它负责：

- 数据库打开、迁移、备份与权限设置。
- 记录查询、搜索、分页、插入或刷新、收藏、分类、摘要和删除。
- 保留期事务、批量清理与自定义分类迁移。
- 在测试中使用临时数据库和可注入的故障点。

Repository 成功前，Store 不得改变对应的持久化 UI 状态。

### 6.4 ClipboardCaptureService

负责幂等启动、暂停、恢复和读取系统粘贴板。服务把捕获事件交给 PrivacyGuard，再交给 Repository；它不直接修改 SwiftUI 状态。

服务必须：

- 在重复 start 调用时保持单一计时器或单一监控任务。
- 捕获变化时记录当时的前台应用 bundle ID，供排除规则使用。
- 自己写入粘贴板后更新 changeCount，避免把应用复制动作重新捕获。
- 把分类和持久化工作移出主线程。

### 6.5 PrivacyGuard

负责应用排除、大小限制和高可信敏感内容检测。它返回 allow 或带原因的 skip，不记录被跳过的正文。

默认单条文本上限为 1 MiB。高可信规则至少覆盖 PEM 私钥头、常见带固定前缀的 API Token，以及通过 Luhn 校验的银行卡候选。模糊密码猜测不用于默认拦截，以降低误报。

首批高可信 Token 规则限定为：PEM PRIVATE KEY 头；sk-、ghp_、github_pat_、xoxb-/xoxp-/xoxa-/xoxr-/xoxs- 前缀后至少 20 个 ASCII 字母、数字、下划线或连字符；AWS AKIA 加 16 位大写字母或数字；以及去除分隔符后为 13 至 19 位且通过 Luhn 校验的银行卡候选。规则只返回类型和跳过原因，不保存匹配文本。

前台应用识别属于尽力而为能力，设置界面必须说明切换应用过快时可能无法准确识别来源。

### 6.6 AIService

AIService 是 actor 隔离的任务协调器。任务包含固定 itemID、操作类型、输入快照和 provider，不读取完成时的当前选择。

Provider 分为：

- disabled：零网络请求、零进程启动。
- localOllama：只接受 localhost、127.0.0.1 或 ::1。
- remoteHTTPS：只接受 HTTPS，并要求用户明确启用和首次发送确认。

服务不自动启动 Ollama。可用性检查超时为 3 秒，生成请求超时为 30 秒，最大响应体为 1 MiB。所有请求支持取消、HTTP 状态检查和结构校验。分类结果必须属于请求时提供的允许分类集合。

远程授权按规范化的 scheme、host 和 port 保存；地址变化即撤销旧授权。可选访问凭据存入 Keychain，不进入 UserDefaults、数据库或日志。Provider 自己拼接固定 API 路径，用户输入不得直接成为请求路径。

切换记录不会改变任务目标；关闭详情或重新发起同类任务时取消旧任务。摘要成功后按 itemID 持久化，改写结果仅交给当前会话状态。

### 6.7 HotkeyService

注册新快捷键前保留旧配置。只有系统注册成功后才持久化新快捷键；冲突或无效组合返回可显示错误，并继续保留旧快捷键。

## 7. 数据模型与迁移

2.0 保留现有 Bundle ID，避免用户默认设置被切换到新域。显示版本统一为 2.0.0，构建号独立递增。

clipboard_items 至少包含：

- id
- content
- content_hash
- builtin_category
- custom_category_id
- created_at
- last_copied_at
- copy_count
- is_favorite
- ai_summary
- deleted_at

custom_categories 至少包含 id、name、prompt、sort_order、is_enabled、created_at 和 updated_at。ai_usage 只包含操作类型、时间、provider、模型、耗时、成功状态和错误码，最多保留 200 条。

自定义分类从 UserDefaults 迁移到 custom_categories 表，记录通过稳定 ID 引用分类。旧记录的分类字符串按名称精确匹配已导入分类；无法匹配的唯一字符串转成禁用的“已恢复分类”，保留显示名称但不参与自动分类，直到用户清除或迁移。删除分类时必须选择清除标签或迁移到另一个分类，不能留下孤儿字符串。

content_hash 使用 SHA-256。相同文本再次出现时，Repository 对哈希命中的候选执行正文确认；匹配后更新 last_copied_at、增加 copy_count 并移动到顶部，同时保留收藏、分类和摘要。保留期以 last_copied_at 为准。

搜索使用 SQLite 索引和分页，默认页大小为 100，快速面板最多读取前 50 条。若运行环境支持 FTS5，则建立并维护全文索引；若不可用，回退到带 LIMIT 的参数化 LIKE 查询。所有用户输入通过绑定参数传入。

首次迁移前创建时间戳数据库备份。迁移在事务内执行；失败时回滚并保留原数据库，应用进入只读恢复状态，显示错误与备份位置，不创建空库覆盖用户数据。

数据库目录权限设置为 0700，数据库及附属文件设置为 0600，并从系统云备份中排除。

Repository 在应用启动、用户确认保留期变化以及每 24 小时执行一次保留期清理。清理和内存结果刷新由同一个 Store 操作协调。

## 8. 关键数据流

### 8.1 捕获

系统粘贴板变化 → CaptureService 捕获文本与来源应用 → PrivacyGuard 判断 → Repository 插入或刷新 → ClipboardStore 更新当前查询结果 → UI 显示非敏感提示。

### 8.2 复制

用户选择记录 → Store 请求 CaptureService 写入粘贴板 → 服务更新 changeCount → Repository 刷新 last_copied_at 与 copy_count → 关闭快速面板并显示已复制状态。若粘贴板写入成功但元数据刷新失败，复制仍视为成功，同时显示“已复制，但历史元数据更新失败”的可重试警告。

### 8.3 AI

用户选择操作 → Store 创建固定 itemID 的任务 → AIService 校验 provider 与网络边界 → 请求或本地处理 → 校验响应 → Store 按 itemID 应用结果；目标已删除时丢弃结果并记录脱敏诊断。

### 8.4 删除与撤销

单项删除先由 Repository 写入 deleted_at，Store 从当前结果移除并注册 8 秒 Undo。撤销窗口结束后执行最终删除。批量清理在确认后使用单一事务，并原子刷新列表和选择。

## 9. 错误处理与诊断

错误分为 database、clipboard、hotkey、privacy、AI、migration 和 releaseConfig。每类错误包含稳定错误码、用户可读说明和可选恢复动作。

- 成功使用轻量短暂提示。
- 可恢复失败显示内联错误，并提供重试或设置入口。
- 数据库与迁移失败使用持续可见的阻断界面，禁止继续制造假成功。
- 日志使用 Logger，默认采用 privacy 标记，不记录剪贴板正文、模型输入或生成结果。
- 诊断导出只包含应用版本、系统版本、错误码、时间、provider 类型和脱敏配置状态。

## 10. 测试策略

新增 XCTest target，并把服务依赖改为协议或可注入实现。

### 10.1 单元测试

- 分类规则与中英文边界。
- PrivacyGuard 的允许、排除、敏感规则和 1 MiB 上限。
- 重复内容刷新时间、计数并保留元数据。
- 保留期使用 last_copied_at。
- 自定义分类删除与迁移。
- AI 本地地址、远程 HTTPS、响应大小、状态码和分类白名单。
- 快捷键成功、冲突和回滚。

### 10.2 Repository 与迁移测试

- 新库创建、旧表迁移、UserDefaults 分类迁移。
- CRUD、分页、搜索和事务。
- 写入失败、只读数据库、损坏数据库和迁移回滚。
- U+0000 等合法 Swift 字符串不会因 C 字符串长度处理而静默截断。

### 10.3 并发测试

- 记录 A 发起任务后选择 B，结果只能写回 A。
- 取消任务后不得落库。
- 同时发起重复操作只能保留定义的最新任务。
- Store 与 Repository 在严格并发检查下无非 Sendable 共享状态警告。

### 10.4 UI 与人工验收

- 快速面板自动聚焦、方向键、Return、Command-Return、Escape。
- 收藏、删除、撤销、监听暂停和侧栏恢复。
- 设置快捷键冲突和 AI 隐私确认。
- 浅色、深色、增强对比度、减少透明度、VoiceOver 和不同窗口尺寸。

## 11. 性能与质量门槛

- 当前 Apple Silicon 开发机的 Release 构建中，10,000 条合成文本记录下，连续 20 次搜索的第 95 百分位低于 100 ms。
- 当前 Apple Silicon 开发机的 Release 构建中，连续 20 次快速面板热启动的第 95 百分位低于 200 ms。
- 大文本分类、哈希、搜索和数据库操作不阻塞主线程。
- disabled AI 模式产生零网络请求和零进程启动。
- Debug、Release 和 Analyze 均成功。
- Swift 严格并发检查与项目构建不产生源码警告。
- 所有 XCTest、现有规则检查及新增打包验证通过。

## 12. 发布与文档

- 版本统一为 2.0.0，保留现有 Bundle ID。
- Release 同时构建 arm64 与 x86_64。
- 建立项目内 build、test 和 package 入口，从干净构建生成 DMG。
- Release 开启 Hardened Runtime，验证应用包和 DMG 完整性。
- Developer ID 签名、公证和 staple 需要有效证书；当前机器没有证书时，产物只能标记为本地测试分发。
